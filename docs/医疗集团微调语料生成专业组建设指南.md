# 医疗集团微调语料生成专业组建设指南

## 一、项目概述

### 1.1 背景与目标

本指南旨在帮助医疗集团中心利用 TotalSegmentator 医学影像分割平台，组建专业团队，系统性地生成高质量的多模态医学影像微调语料，用于训练医疗领域专用的大语言模型（如 Qwen2-VL、GPT-4o 等）。

### 1.2 平台核心能力

| 能力模块 | 描述 |
|---------|------|
| **医学影像分割** | 支持 117+ 种解剖结构的 CT/MR 自动分割 |
| **多模态问答生成** | 结合 AI 分割结果和多模态大模型生成专业问答对 |
| **模板化语料生成** | 提供器官识别、位置描述、形态分析等多类型问答模板 |
| **数据标注平台** | 集成 Label Studio 支持人工审核和修正 |
| **训练数据导出** | 支持 ShareGPT、Alpaca 等主流训练格式 |

### 1.3 技术架构

```
┌─────────────────────────────────────────────────────────────────┐
│                    医疗集团中心平台                              │
├─────────────────────────────────────────────────────────────────┤

│  │ Web 前端    │  │ FastAPI 后端│  │ TotalSeg AI│              │
│  │ (Next.js)   │◄─►│ (Python)   │◄─►│ 分割引擎  │              │

│         │               │                │                       │

│  │  PostgreSQL │ MinIO │ Redis │ Label Studio   │               │
```

### 2.2 各角色职责详解

#### 2.2.1 项目总监（1人）

**任职要求：**
- 集团信息中心或医务部门负责人
- 具备医疗信息化项目管理经验
- 了解 AI/大模型基本概念

**主要职责：**
- 制定项目目标、时间表和里程碑
- 协调下级医疗机构资源调配
- 审批语料生成规范和质量标准
- 定期检视项目进度，解决跨部门协调问题
- 对外汇报项目成果

#### 2.2.2 医学专家组（3-5人）

**人员构成：**

| 角色 | 数量 | 来源 | 专业要求 |
|-----|-----|------|---------|
| 放射科医师 | 1-2人 | 集团/下级医院 | 副主任医师以上，精通 CT/MR 影像诊断 |
| 临床科室医师 | 1-2人 | 各专科 | 主治医师以上，熟悉临床诊断流程 |
| 药师（可选） | 1人 | 临床药学 | 主管药师以上，了解影像相关用药 |

**主要职责：**
- 审核 AI 生成的器官分割准确性
- 编写和优化问答模板
- 审核 LLM 生成的专业回答
- 修正医学术语和诊断表述
- 制定临床场景覆盖规范

#### 2.2.3 技术支持组（2-3人）

**人员构成：**

| 角色 | 数量 | 专业要求 |
|-----|-----|---------|
| 平台运维工程师 | 1人 | 熟悉 Docker、Linux 系统运维 |
| AI/数据工程师 | 1-2人 | 熟悉 Python、了解大模型微调流程 |

**主要职责：**
- 部署和维护 TotalSegmentator 平台
- 配置 LLM 接口（OpenAI 兼容 API）
- 管理数据存储（MinIO、PostgreSQL）
- 导出和转换训练数据格式
- 对接下级医院的影像数据传输

#### 2.2.4 质量控制组（2-3人）

**人员构成：**

| 角色 | 数量 | 要求 |
|-----|-----|------|
| 质量审核专员 | 1-2人 | 医学背景，细致认真 |
| 抽检专员 | 1人 | 了解数据质量评估方法 |

**主要职责：**
- 执行分层抽检（按器官类型、问题类型）
- 记录和统计语料质量问题
- 跟踪问题修复闭环
- 编写质量报告

### 3.1 阶段一：准备期（2周）

#### 3.1.1 团队组建

| 任务 | 责任人 | 产出物 |
|-----|-------|-------|

#### 3.1.2 平台环境准备

```bash
# 技术支持组执行
# 1. 克隆项目
git clone <项目地址>
cd TotalSegmentator

# 2. 启动基础服务
docker-compose up -d

# 3. 如需 Label Studio 标注功能
docker-compose --profile labelstudio up -d

# 4. 安装 Python 依赖并启动后端
pip install -e .
cd api && pip install -r requirements.txt
python -m uvicorn main:app --host 0.0.0.0 --port 28000

# 5. 启动前端
cd web && npm install && npm run dev
```

### 3.2 阶段二：试运行期（2周）

#### 3.2.1 小批量验证

**目标：** 完成 50-100 例样本的全流程验证

**各角色工作内容：**

| 角色 | 工作内容 |
|-----|---------|
| 技术支持组 | 上传测试 CT 数据，运行分割，生成问答对 |

#### 3.2.2 系统使用流程

```
1. 上传 CT/MR 文件
   └─► Web界面上传 NIfTI/DICOM 文件

2. AI 自动分割
   └─► 系统调用 TotalSegmentator 识别 117+ 种器官

3. 配置问答生成
   ├─► 选择问答类型（器官识别/位置描述/诊断分析等）
   ├─► 选择是否使用 LLM 多模态生成
   └─► 设置每个切片生成的问答数量

4. 预览与审核
   ├─► 逐条查看生成的问答对
   ├─► 在线编辑修正不准确的内容
   └─► 选择要导出的数据项

5. 导出训练数据
   └─► 下载 JSON 格式训练语料
```

| 维度 | 评估标准 | 权重 |

| 格式不规范 | 报告格式不符合临床规范 | 按标准模板调整 |

### 4.2 医学专家操作指南

#### 4.2.1 分割结果审核

**步骤：**

1. 在会话列表中选择待审核的分割任务
2. 使用切片浏览器逐层查看分割结果
3. 检查以下内容：
   - 器官边界是否准确
   - 是否有漏检的器官
   - 是否有误检（将非器官区域标记为器官）
4. 记录问题切片和器官，反馈给技术支持组

**分割质量判断标准：**

| 等级 | 描述 | 处理方式 |
|-----|------|---------|
| 优秀 | 边界准确，无漏检误检 | 直接用于语料生成 |
| 良好 | 边界基本准确，小幅偏差 | 可用于语料生成 |
| 一般 | 部分器官边界不清 | 需在问答中标注"边界欠清晰" |
| 差 | 严重漏检或误检 | 不用于语料生成 |

#### 4.2.2 问答内容审核与修正

**审核要点：**

1. **术语准确性**
   - 器官名称是否使用标准医学术语
   - 解剖位置描述是否正确

2. **诊断合理性**
   - 描述是否过于肯定（应保持谨慎）
   - 是否有不恰当的疾病诊断

3. **表述规范性**
   - 是否符合影像报告书写规范
   - 语言是否通顺、专业

**修正示例：**

| 原始回答 | 问题 | 修正后 |
|---------|-----|-------|
| "肝脏明显增大" | 无依据的诊断 | "肝脏显示，形态正常，密度均匀" |
| "脾在左边" | 表述不专业 | "脾脏位于左上腹，形态规则" |
| "可能是肝癌" | 过度诊断 | "肝实质密度均匀，未见明显占位" |

### 4.3 技术支持组操作指南

#### 4.3.1 LLM 配置

**路径：** 训练导出面板 → 配置 → LLM 设置

```json
{
  "enabled": true,
  "provider": "openai",
  "base_url": "https://api.openai.com/v1",
  "api_key": "sk-xxxxx",
  "model": "gpt-4o",
  "temperature": 0.7,
  "max_tokens": 1024,
  "timeout": 120
}
```

**支持的多模态模型：**
- OpenAI: GPT-4o, GPT-4 Vision
- 阿里云: Qwen-VL-Plus, Qwen-VL-Max
- 其他 OpenAI 兼容接口

#### 4.3.2 问答模板配置

**路径：** 训练导出面板 → 配置 → 问答模板

**可选模板类型：**

| 模板类型 | 开关 | 优先级 |
|---------|-----|-------|
| 器官识别 (organ_identification) | ✅ 启用 | ⭐ 重点 |
| 位置定位 (organ_location) | ✅ 启用 | |
| 形态描述 (organ_description) | ✅ 启用 | ⭐ 重点 |
| 诊断分析 (diagnostic_analysis) | ✅ 启用 | ⭐ 重点 |
| 影像报告 (comprehensive_report) | ✅ 启用 | |
| 解剖关系 (anatomical_relation) | ✅ 启用 | |
| 临床意义 (clinical_relevance) | ✅ 启用 | |

#### 4.3.3 批量生成语料

**步骤：**

1. 在会话列表中选择已完成分割的会话
2. 打开"训练导出"面板
3. 配置生成参数：
   - 切片步长：建议 5-10（每隔 N 张切片生成一组问答）
   - 每切片问答数：建议 3-5 条
   - 是否使用 LLM：建议开启以提高质量
4. 点击"生成预览"
5. 等待生成完成，审核内容
6. 选择要导出的数据项
7. 点击"导出"下载 JSON 文件

### 4.4 质量控制组操作指南

#### 4.4.1 抽检流程

**抽检比例建议：**

| 阶段 | 抽检比例 | 说明 |
|-----|---------|------|
| 试运行期 | 100% | 全量审核 |
| 规模化初期 | 30-50% | 重点关注新类型 |
| 规模化中后期 | 10-20% | 随机抽检 |
| 质量优化期 | 20-30% | 重点抽检问题类型 |

**抽检记录表：**

| 字段 | 说明 |
|-----|------|
| 样本ID | 问答对唯一标识 |
| 器官类型 | 涉及的主要器官 |
| 问题类型 | 问答类别 |
| 质量评分 | 1-5 分 |
| 问题描述 | 具体问题说明 |
| 修正建议 | 改进方向 |

#### 4.4.2 质量报告模板

### 5.1 支持的器官列表（部分）

系统支持 117+ 种解剖结构，以下为主要器官分类：

**腹部器官：**
- 肝脏 (liver)、脾脏 (spleen)、胰腺 (pancreas)
- 左肾 (kidney_left)、右肾 (kidney_right)
- 胆囊 (gallbladder)、胃 (stomach)
- 十二指肠 (duodenum)、小肠 (small_bowel)、结肠 (colon)

**胸部器官：**
- 左肺上叶、下叶 (lung_upper/lower_lobe_left)
- 右肺上叶、中叶、下叶 (lung_upper/middle/lower_lobe_right)
- 心脏 (heart)、主动脉 (aorta)、气管 (trachea)

**脊柱与骨骼：**
- 颈椎 C1-C7 (vertebrae_C1-C7)
- 胸椎 T1-T12 (vertebrae_T1-T12)
- 腰椎 L1-L5 (vertebrae_L1-L5)
- 骶骨 (sacrum)、髋骨 (hip_left/right)

### 5.4 常见问题解答

**Q1: LLM 生成速度慢怎么办？**

A: 可以考虑以下方案：
- 使用更快的模型（如 GPT-4o-mini）
- 减少每切片问答数量
- 增大切片步长
- 使用本地部署的模型

**Q2: 分割结果不准确怎么办？**

A:
- 检查输入图像质量（分辨率、对比度）
- 尝试不同的分割任务（total, fast 等）
- 严重不准确的案例不用于语料生成

**Q3: 如何扩展自定义问答模板？**

A: 在 `training/llama_factory/qa_templates.py` 中添加新模板，或通过 Web 界面的"自定义模板"功能添加。
